## 1. 领域层级模型（定稿）

```
车架设计图纸（上游研发部门）
      │
      ▼
模具 MOLD-XXXX（SN 追溯对象 · 一套模具 = 一个工单）
      │
      ├── 部件 BOM（★设计科产出：模具 → 加工件清单）
      │     ├── 自制件（铁板 CNC 加工）
      │     │     ├── 规格：铁板型号（厚度 × 尺寸，固定规格字典）
      │     │     ├── 图纸号 / 编程号（标识工程文件）
      │     │     └── ★加工组（编程科细分：同规格件合并 → 同刀具加工）
      │     └── 外购件（导柱 / 导套 / 标准件）
      │           └── ★项目科申购 → 仓库科管理库存
      │
      ├── CNC 加工（按【加工组】排产：组工时 = 装夹 + 单件加工 × 件数）
      ├── 热处理 / EDM（按件）
      ├── 钳工装配（★齐套检查通过后装配——钳工=装配，同一环节）
      └── 试模（产出样板产品，在报工中记录，不单独跟踪）
```

## 2. 原料层：铁板规格 + 批次

| 项 | 设计 |
|---|---|
| 规格字典 | 固定几种型号：**厚度 × 尺寸**（如 8mm×2000×1000、12mm×2000×1000、20mm×1500×3000 …） |
| 批次管理 | 每批铁板**入厂贴码**（批次号 + 规格 + 供应商/炉号），报工/发料扫码 |
| 追溯 | 加工件 → 消耗的铁板批次（反向追溯延伸：模具 → 加工件 → 铁板批次） |

> 数据表：`steel_specs`（规格字典）、`material_batches`（批次，关联规格）。

## 3. 分级 BOM（★逐步细分的机制）

BOM 不是一次性建好，而是**两个环节逐步细化**：

| 环节 | 产出 | 负责人 |
|---|---|---|
| ① 设计阶段 | **模具 → 加工件清单**（部件 BOM：自制件 + 外购件，含规格/图纸号） | 设计科 |
| ② 编程阶段 | **加工件 → 加工组细分**（按规格合并、定编程号/刀具、算组工时） | 编程科 |

- 设计科先建"模具 BOM"（有多少自制件、外购件）；
- 编程科再对自制件做**加工分组**（哪些件一起加工）并分配编程号；
- 排产时 CNC 工序按**加工组**排，不是按单个件。

> 职责权限：设计科 = BOM 维护；编程科 = 加工组细分；两者数据联动（BOM 完成后编程才可分组）。

## 4. CNC 成组加工与排产粒度（★算法升级）

### 4.1 为什么分组
加工件大小决定**刀具（针头）**：大的件用大刀一起加工，小的件用小刀一起加工，减少换刀、提升效率。

### 4.2 分组规则（演示采用，可配置）

| 规则 | 说明 | 状态 |
|---|---|---|
| 按件大小两档（大件组 / 小件组） | 简化清晰，演示足够 | **演示默认** |
| 按厚度分组 | 贴近实际选刀逻辑 | 可配置扩展 |
| 按刀具规格 / 编程号分组 | 最细 | 二期 |

> 需求方暂不确定实际分组规则——演示先按"大小两档"，规则做成**可配置**（编程科在系统里可自定义分组），不影响演示主流程。

### 4.3 加工组工时与排产
```text
加工组工时 = 装夹时间 + 单件加工时间 × 组内件数
例：大件组（3 件）= 装夹 0.5 天 + 每件 0.8 天 × 3 = 2.9 天

排产对象 = 加工组（而非单件）
  CNC 工序的"标准工时" = 该组所有组的工时之和（模具级 CNC 总工时）
  逾期预警按模具整体交期倒排（算法不变，只是工时粒度细化）
```

## 5. 外购件：项目申购 → 仓库库存

| 环节 | 角色 | 系统动作 |
|---|---|---|
| 申购 | 项目科 | 按模具 BOM 发起外购件申购（数量、需求日期） |
| 到货入库 | 仓库科 | 外购件到货 → 入库存台账（数量、批次可选） |
| 齐套查询 | 仓库科/车间 | 按模具查"外购件是否齐" |

> 第一期不做完整采购流程（无供应商管理/采购单审批），只做：**申购记录 + 库存台账 + 齐套状态**。

---

## 6. 齐套检查（钳工装配前置条件）

钳工装配前，系统按**模具 BOM 清单**自动核对：

```text
齐套条件（全部满足才允许进入钳工装配）：
  ✓ 所有自制件对应加工组 已完成 CNC（及热处理/EDM 等后续工序）
  ✓ 所有外购件 库存数量 ≥ BOM 需求数量（或已到货）
  ✓ 对照清单逐项核对（清单 = 设计科 BOM + 编程科分组）
```

> 演示效果：加工件未齐时，钳工任务显示"待齐套（缺 N 项）"，齐套后解锁。

## 9. 追溯链（加深）

```text
正向：模具 SN → 加工件清单（自制/外购）→ 加工组 → CNC/热处理/EDM 履历 → 铁板批次
反向：铁板批次 → 加工件 → 模具 SN
```

## 10. 排产算法联动（更新 04 文档）

- CNC 工序工时 = Σ 各加工组工时（4.3）；
- 工序粒度：设计(2d) → CNC 加工组(≈3d) → 热处理(2d) → EDM(3d) → 钳工装配(2d) → 试模(2d)；
- 倒排逻辑不变，CNC 的"可排工位 + 负载"细化到加工组维度。

### 附：加工组规则思考框架（供需求方参考，不急着答）

实际分组通常由**效率驱动**，可参考以下维度想清楚：
1. **刀具决定**：不同大小/厚度用不同刀具 → 同刀具的件一组（换刀最费时）；
2. **装夹方式**：同尺寸板材可一次装夹多个件 → 同板材规格的件一组；
3. **精度要求**：精加工件与粗加工件分开（避免刀具磨损影响精度）；
4. **交期优先级**：急件可单独成组插队。

> 演示系统先把规则做成「分组类型字段 + 组工时计算」，将来无论按哪种规则，只需改分组逻辑和种子数据。
