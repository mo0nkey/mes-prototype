## 1. 系统架构设计

### 1.1 架构风格
**前后端分离的单体应用**（Monolith）——所有功能在一个后端进程内，不引入微服务。理由：演示规模（30 工位并发）单体完全胜任；单体便于理解全链路，符合"边学边建"目标。

### 1.2 分层结构

| 层 | 技术 | 职责 |
|---|---|---|
| 展示层（前端 SPA） | Vue 3 + Element Plus + Vite + ECharts | 页面渲染、表单交互、看板图表、扫码输入模拟 |
| 接口层（REST API） | FastAPI 路由 + Pydantic 校验 | 接收前端请求、参数校验、返回 JSON |
| 业务服务层 | Python 业务模块（8 个） | 工单/排产/执行/追溯/看板/报表/主数据/系统 |
| 数据访问层 | SQLAlchemy ORM | 对象关系映射、事务管理 |
| 存储层 | SQLite（WAL 模式） | 数据持久化；预留 PostgreSQL 切换（模型兼容） |

### 1.3 业务模块划分（后端 8 个服务模块）

| 模块 | 核心职责 | 对应 SRS |
|---|---|---|
| 主数据服务 | 产品/工艺路线/BOM/物料/SN 规则/原料批次/Excel 导入 | 4.1 |
| 工单服务 | 工单 CRUD、状态机流转、交期风险列表 | 4.2 |
| 排产服务 | 倒排计算、负载校验、逾期预警、手动调整重算、派工落库 | 4.3 |
| 执行服务 | 开工、原料批次绑定、报工（单件/批量）、工序流转、安灯 | 4.4 |
| 追溯服务 | 正向（SN→履历）、反向（批次→SN）查询与导出 | 4.5 |
| 看板服务 | 进度/安灯/交期风险三块看板的数据聚合 | 4.6 |
| 报表服务 | 工单进度报表、追溯导出 | 4.7 |
| 系统服务 | 登录鉴权（JWT）、RBAC 权限、操作日志、演示数据重置 | 6 |

### 1.5 关键技术决策

| 决策点 | 选择 | 理由 |
|---|---|---|
| 认证方式 | JWT + RBAC 角色权限 | 无状态、实现简单，5 种角色映射 SRS §3 |
| 扫码实现 | 输入框自动聚焦 + 回车触发（键盘模拟扫码枪） | 演示零硬件成本，真实扫码枪本质就是"快速键盘输入+回车" |
| 看板刷新 | 前端轮询（每 5-10 秒） | 演示规模足够；WebSocket 属过度设计，二期再考虑 |
| 时间处理 | 简化工作日历：每天 8 小时（8:00-17:00，午休 1 小时），周末可配置是否上班 | 演示用标准工时即可，算法可读性强 |
| 排产算法 | 交期倒排 + 贪心选窗 + 手动调整重算 | 见 §4.1，可控可讲解 |
| 并发控制 | 单进程 + SQLite WAL，报工采用事务 | 30 工位演示零压力 |
| Excel 导入 | 前端上传 → 后端 openpyxl 解析 → 校验 → 落库 | 主数据批量导入 |

### 2.2 实体关系（核心链路）

```
products ──1:N── process_routes ──1:N── process_route_steps
   │ 1:N                        （每套模具一条工艺路线，含 6 道工序）
   ├──1:N── bom_items ──N:1── materials ──1:N── material_batches
   │                                            （原料批次=反向追溯起点）
   └──1:N── work_orders ──1:N── work_order_sns（SN 台账，每套模具一个 SN）
                │ 1:N
                ├── schedule_plans ──N:1── stations ──N:1── lines
                │            （排产：工单×工序×工位×时间窗）
                ├── work_reports（报工记录，追溯的"工序履历"）
                └── batch_bindings ──N:1── material_batches
                     （SN ↔ 原料批次 多对多，正向/反向追溯的交汇点）
stations ──1:N── andon_events（安灯挂在工位上）
```

### 2.3 追溯数据链（设计要点）

- **正向追溯**（SN→用料）：`work_order_sns.sn` → `work_reports`（按 step_no 排序的完整履历）→ `batch_bindings` → `material_batches`（批次号/物料/供应商）
- **反向追溯**（批次→SN）：`material_batches.batch_no` → `batch_bindings` → 使用该批次的 SN 列表及其工单
- 追溯核心表（12/14/15 三张）**永久保留**，普通日志按可配置周期清理

## 3. 核心流程设计

### 3.1 排产倒排算法（★需求方重点）

**目标**：承诺交期已定但产能跟不上时，给出"最晚开工时间"建议、逾期预警，并允许手动调整。

```text
输入：工单(产品, 数量, 承诺交期) / 工艺路线步骤(每步标准工时) / 工位负载(已排计划)
工作日历：每天 8 小时，周末可配置

1. 从最后一道工序开始向前倒排：
   cur_end = 承诺交期的下班时间
   对每道工序（从后往前 step = N → 1）：
     a. 工序时长 = 标准工时 × 数量          （模具通常数量=1）
     b. 在允许工位组中寻找"最晚可用时间窗"：
        取该工位上 cur_end 之前最晚的空闲时间段
        （空闲 = 该工位已排计划之外的连续时段）
     c. 工序最晚结束 = 找到的时间窗结束
        工序最晚开始 = 最晚结束 - 工序时长
     d. 相邻工序之间留 0.5 天缓冲（可选配置）
     e. cur_end = 工序最晚开始

2. 逾期判定：
   若首道工序的最晚开始 < 当前时间 → 产能跟不上
      → 预计延期天数 = (当前时间 - 首工序最晚开始) 折算为工作日
      → 输出"按当前排期将延期 X 天"预警

3. 输出建议排期（calc_type = auto）：
   每道工序 → 建议工位 + 建议开始/结束时间 + 风险等级(正常/临期/逾期)

4. 手动调整（calc_type = manual）：
   计划员可：改开始时间（前移/后移） / 换工位
   每次调整后系统**即时重算**：
     - 同一工位时间冲突？→ 提示冲突工单
     - 是否仍满足交期？→ 更新风险等级
   ⚠️ 只提示、不强制——"机器建议，人来拍板"
   交期无法满足时，计划员可标记"与客户协商中"并留痕

5. 确认派工：排产计划落库（schedule_plans, status=待执行）
   各工位生成"待执行任务清单"
```

**演示效果**：场景 3 中，给一套交期紧的模具排产 → 系统提示"按当前负载将延期 3 天" → 计划员把 EDM 精加工从 EDM1# 换到空闲的 EDM3# → 系统重算后显示"可按时完成，风险=正常"。

### 3.2 工单状态机

```text
草稿 ──[提交]──▶ 已排产 ──[确认派工]──▶ 已派工 ──[首工序开工]──▶ 生产中
生产中 ──[末道工序报工完成]──▶ 完工 ──[质检/归档]──▶ 关闭
（任何状态都可被管理员[作废]，作废记录留痕）
```

转换规则：每步状态变更写 operation_logs（谁、何时、从哪到哪）。

### 3.3 报工流转流程（单件 & 批量）

```text
工位端操作工：
1. 打开"我的任务"（按工位筛选待执行任务）
2. 扫码开工：输入/扫 SN → 校验：
   - SN 属于当前工单 ✓
   - 当前工序 = 该工位负责的工序 ✓
   - 工单状态 = 生产中（首道工序开工时由"已派工"→"生产中"）
3. 原料批次绑定（仅当该工序 BOM 有批次追溯物料时）：
   - 扫原料批次标签 → 写入 batch_bindings
4. 报工：
   - 单件模式：录入合格数量(0/1) + 工时 → 提交
   - 批量模式：录入数量 N → 系统确认 N 个 SN（未生成则按规则生成）→ 一次提交
5. 提交后（事务内）：
   - 写 work_reports（每 SN 一条明细）
   - 更新 SN 状态与 current_step_no
   - 非末道工序：下一工序变为"待执行"
   - 末道工序：工单 → 完工
6. 异常：任何环节可触发安灯（缺料/设备/质量/其他），看板亮灯，班组长处理解除
```

### 3.4 追溯查询流程

```text
正向（输入 SN）：
  SN → 该 SN 的全部报工记录（按工序排序）
     → 每步的：时间、工位、操作工、合格/不良数量、工时
     → 关联的原料批次（批次号、物料、供应商、入库时间）
  ── 输出：完整工序履历表 + 用料清单

反向（输入原料批次号）：
  批次号 → 该批次被哪些工单/SN 使用（列表）
     → 每个 SN 的当前状态与工序进度
  ── 输出：受影响模具清单（质量问题快速定位用）
```
