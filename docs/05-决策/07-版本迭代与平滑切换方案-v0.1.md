# MES 演示原型系统 · 版本迭代与平滑切换方案

> 版本：v0.1
> 目的：回答"依据现有文档体系，如何持续迭代需求，同时保持线上平滑切换版本"

---

## 1. 核心原则：文档是需求的唯一权威

```text
需求变更流程（本项目的节奏）：
提出变更 → 更新对应文档（SRS/设计/专题）→ 文档版本号 +1 → 评审确认 → 开发 → 发布
```

| 文档 | 职责 | 版本锚点 |
|---|---|---|
| SRS v0.2 | 需求范围（做什么） | 每个需求变更都反映于此 |
| 概要设计 / 专题设计 03/04/05 | 方案（怎么做） | 实现依据 |
| 技术实现方案 06 | 工程约定 | 技术演进 |
| **CHANGELOG.md（新增）** | 版本发布记录 | 每个发布版本对应条目 |

> 例：加工组规则未定 → 文档 05 标记"待确认" + 实现用**可配置占位**，规则定了只需改配置和种子数据，**不改架构**。

## 2. 版本号体系（语义化）

```text
主版本.次版本.补丁
v1.0.0  ← 演示验收版（八场景全过）
v0.3.0  ← 看板/报表
v0.2.0  ← 排产（模拟/预警/调整）
v0.1.0  ← 脚手架 + 最小闭环（登录/主数据/建工单）
```

- 每个版本 Git tag + CHANGELOG 条目；
- 每个里程碑交付**可演示版本**（边开发边演示，随时给客户/同事看）。

## 3. 数据库平滑演进（最关键）

### 3.1 用 Alembic 迁移（脚手架第一天就引入）
```text
backend/
├── alembic/
│   ├── versions/001_initial.py      # 建 23 表
│   ├── versions/002_add_xxx.py      # 后续每个变更一个迁移
│   └── ...
```
- 每次 schema 变更 = 新增一个迁移文件（upgrade 升级 + downgrade 回滚）；
- **绝不手工改表**；升级/回滚一条命令。

### 3.2 变更铁律（保证平滑）

| 规则 | 说明 |
|---|---|
| 加列 → 必带默认值或可空 | 旧数据不受影响 |
| 加表 → 不动旧表 | 新旧模块共存 |
| 追溯表（报工/绑定/审核）只增不改 | 历史数据永不改写，保证追溯真实性 |
| 状态机 → 只加状态，不删/不改旧状态 | 旧流程数据仍可解释 |
| 字段改名 → 新旧字段并存一个版本再删 | 兼容过渡期 |

## 4. 线上平滑切换的通用策略

### 4.1 功能开关（Feature Flag）★最适合本项目
```text
config/feature_flags.json（或数据库配置表）
{
  "machining_group_rule": "size",     // 加工组规则：size/厚度/刀具，随时切
  "quality_module": false,            // 二期质检：默认关，开=启用质检节点
  "data_collection": false            // 设备数采：默认关
}
```
- 新功能**默认关闭**，验证稳定后再开 → 未定的需求（加工组规则、质检）用开关承载；
- 演示时开关即改即生效。

### 4.2 API 兼容
- 新增接口不破坏旧接口；字段变更用**可选字段**（旧客户端兼容）；
- API 前缀 `/api/v1`，未来大版本升级用 `/api/v2` 并存。

### 4.3 发布与回滚
| 场景 | 策略 |
|---|---|
| 演示系统 | 版本切换 = 重启 + （可选）重置演示数据；零风险 |
| 未来落地 | **新旧并行**（SRS §5：纸质+系统并行 2-4 周）→ 验证后切换；保留上一版本可回滚 |

### 4.4 灰度（未来多车间时）
- 先试点车间 → 全量（符合 SRS"单车间试点再推广"）。

## 5. 落到本项目的第一批约定（脚手架即生效）

1. 文档目录 docs/ 全部版本化（已做），新增 **CHANGELOG.md**；
2. 脚手架引入 **Alembic**（首个迁移 = 23 表）；
3. **feature_flags 配置**：加工组规则、质检、数采三个开关；
4. API 统一 `/api/v1` 前缀；
5. 追溯三表（work_reports / batch_bindings / review_records）**append-only**（只插不删改）；
6. 种子数据与正式数据分离（seed/ 可重置，正式库走迁移）。

## 6. 演示场景中的体现

- 加工组规则未定时：用大小两档 + 开关切换，演示不受影响；
- 每个里程碑后：文档、CHANGELOG、代码版本三者对齐；
- 未来加质检：feature flag 开启 + 新迁移 + 新页面，旧数据与流程不动。
