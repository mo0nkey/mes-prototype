# MES 演示原型系统 · 需求规格说明书（SRS）草案

> 版本：v0.2（纳入需求方补充需求：交期驱动排产 + 模具行业演示数据）
> 定位：**学习/演练用途的可运行演示原型**，不落地生产，但业务流程与数据模型按真实 MES 标准设计
> 编制依据：与需求方（工厂从业者）多轮澄清访谈

---

## 1. 项目概述

### 1.1 背景与目标
- 需求方为工厂从业人员（汽车零部件模具行业背景），希望通过对 MES 的完整搭建过程，加深对制造执行系统的理解；
- 目标产物：**一套能在单台电脑上运行、用浏览器操作演示的 MES 原型**，覆盖"从工单到追溯"的核心生产执行闭环；
- 成功标准（需求方指定）：**取消纸质流转卡/工票，全部线上流转**（在演示系统中体现为：工单、工序、SN 全流程线上可查、可追溯）；
- **补充目标（需求方新增）**：解决"承诺交期已定但产能跟不上"的排产矛盾——系统要能**智能排期并给出手动调整空间**。

### 1.2 范围边界
- 范围：单车间（演示数据按 30+ 工位的模具车间规模构造）；
- 第一期**明确不做**：质量检验流程、设备管理/数采、WMS/库存管理、自动排产引擎（APS 全自动）、考勤、人员技能管理、移动端 APP、与外部系统实时对接。

## 2. 业务画像（需求澄清结论）

| 维度 | 结论 | 设计影响 |
|---|---|---|
| 行业/类型 | 离散制造，**汽车零部件模具制造** | 单件生产、交期敏感、工序链长 |
| 生产模式 | **按单生产为主**（MTO/ETO 性质），少量备货 | 每套模具=独立工单=独立 SN |
| 追溯粒度 | **单件 SN**（模具编号即 SN，客户/外部规定规则） | SN 规则可配置、防重复校验，正向/反向追溯 |
| 排产核心诉求 | **交期锁定 + 产能跟不上 → 智能排期 + 手动调整** | 交期驱动倒排、逾期预警、冲突校验（见 4.3） |
| 物料追溯 | 报工时扫原料批次标签 | 原料批次 → SN 绑定关系落库 |
| 主数据来源 | PDM/图纸系统导出 Excel 导入 | 原型内置"Excel 导入 + 种子数据"双通道 |
| 质检 | 第一期不做 | 追溯不含检验结果；预留字段便于二期扩展 |
| 设备看板 | 不做设备状态，只做进度+安灯 | 安灯由人工触发/解除 |
| 报工 | 扫码枪 + 工位电脑（浏览器），**支持批量报工** | 演示时可用键盘回车模拟扫码 |
| 网络/部署 | WiFi 稳定；本地部署 | 原型：单机本地运行，浏览器访问 |
| 数据留存 | 按客户要求（不确定） | 追溯核心数据长期保留，归档策略可配置 |

## 4. 功能需求（第一期 MVP）

### 4.1 主数据管理（地基）
- **产品（模具）**：模具编码（=SN 规则前缀）、名称（如"某车型前门内板拉延模"）、规格、标准生产周期、默认工艺路线；
- **工艺路线（模具典型）**：设计 → CNC 粗加工 → 热处理 → EDM 精加工 → 装配 → 试模；每道工序含工序编号、标准工时、可排产工位（如 CNC 1#/2#、EDM 1#、装配线）；
- **BOM**：模具 → 物料清单（模架、型腔材料、标准件等，标注是否批次追溯）；
- **物料**：编码、名称、规格、单位、批次管理标志；
- **SN 规则配置**：按产品/客户配置（前缀 + 年月 + 流水号，如 MOLD-2025-0001），生成时防重校验；
- **数据入口**：Excel 导入模板 + 内置演示种子数据（模具车间：3 条产线区、30 个工位、5-8 套代表性模具工艺、若干原料批次）。

### 4.2 工单管理
- 工单创建：选择模具产品、数量（通常 1 套）、**承诺交期（客户已定，硬约束）**、优先级、计划开始时间；
- 工单状态机：**草稿 → 已排产 → 已派工 → 生产中 → 完工 → 关闭**；
- 状态变更留痕（谁、何时、从哪到哪）；
- 工单查询/筛选（按状态、产品、交期、产线），**交期风险列表**（逾期/临期高亮）。

### 4.3 排产派工（模拟排期 + 交期驱动智能排期 + 手动调整）★需求方新增重点
- **模拟排期（★需求方新增）**：项目启动经线下启动会确认产品计划后，排期先走**模拟模式**（草稿，不占用正式产能、不派工）；模拟结果在**线上会议演示**，确认后**转为正式排期**，再进入下方排产逻辑；之后跟踪项目/工单进度；
- **交期倒排计算**：按工艺路线标准工时从承诺交期倒推，计算每道工序的"最晚开工/完工时间"，生成建议排期；
- **产能/负载校验**：检查所派工位的已排负载，识别冲突（同一工位时间重叠）；
- **逾期预警**：实时计算"预计完工时间 vs 承诺交期"，输出**风险等级**（正常/临期/逾期）与**预计延期天数**；产能跟不上时明确提示"按当前排期将延期 X 天"；
- **手动调整**（智能建议 + 人来拍板）：
  - 调整工序开始时间（前移/后移）；
  - 更换工位（如 CNC 1# 换到 CNC 2#）；
  - 系统在每次调整后**即时重算**冲突与交期风险，不强制但明确提示后果；
  - 交期无法满足时，计划员可标记"与客户协商中"或确认延期，留痕；
- **派工产出**：生成各工位的"待执行任务清单"。

### 4.4 工序执行（核心闭环）
- **开工**：操作工扫码/选择任务 → 校验 SN 规则与工单状态 → 记录开工时间；
- **原料批次绑定**：报工时扫原料批次标签（如模架钢料批次），绑定到当前模具 SN；
- **报工**：录入完成数量与工时；**支持批量报工**（N 件一次报，同时保留每件明细）；
- **提交审核（★需求方新增）**：报工完成后需**提交确认给上一级**——科室工作由科长审核、厂房工序由车间主任确认；**审核通过才流转下一工序/工种，驳回退回修改**；审核记录全量留痕；
- **完工**：末道工序报工且**审核通过**后工单完工；
- **流转**：本工序**审核通过后**进入下一工序待执行；
- **异常上报（安灯）**：工位触发异常（缺料/设备/质量/其他），可附备注；看板实时亮灯；车间主任确认解除并记录处理结果；
- **交期联动**：任何工序延期都会自动反映到 4.3 的逾期预警。

### 4.5 追溯查询（验收核心）
- **正向追溯**：输入模具 SN → 查询完整工序履历（每道工序时间、工位、操作工）+ 所用原料批次；
- **反向追溯**：输入原料批次号 → 查询该批次被哪些模具 SN 使用；
- 结果支持导出（Excel/CSV）。

### 4.6 看板（演示亮点）
- **生产进度看板**：按产线区/工单显示产量达成率、当前工序、状态（大屏风格）；
- **安灯看板**：各工位异常灯实时状态、持续时长、处理状态；
- **交期风险看板**：全部在产工单的交期状态（正常/临期/逾期），逾期红色高亮。

### 4.7 报表
- **工单进度表**：工单维度显示各工序完成情况、实际 vs 计划、**交期达成情况**；
- **追溯查询导出**（见 4.5）。

## 5. 演示场景（验收用例）

1. **准备**：管理员导入/生成演示数据（模具、工艺、BOM、原料批次、SN 规则）；
2. **计划·正常**：计划员创建 2 套模具工单（交期宽裕），系统倒排给出建议排期，派工到工位；
3. **计划·紧张**：创建 1 套**交期紧迫**的模具工单，系统提示"按当前负载将延期 X 天"——演示**逾期预警**；计划员手动调整（换工位/前移开始时间），系统重算后风险消除——演示**智能排期+手动调整**；
4. **执行**：操作工在工位浏览器上开工 → 扫原料批次 → 批量报工 → 下一工序，直至完工；
5. **安灯**：中途触发一次异常（如缺料），看板亮灯，班组长处理解除；
6. **看板**：切换大屏看板，展示实时进度、安灯状态、交期风险；
7. **追溯**：对一个已完工模具 SN 做正向追溯，对其用过的原料批次做反向追溯；
8. **验证**：全程无纸质流转卡，任何节点状态在系统中可查。

## 7. 技术栈建议（倾向已定，设计阶段最终确认）

需求方编程基础偏业务（主要懂工厂业务），选**学习曲线最平缓、代码可读性强**的方案：

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | Vue 3 + Element Plus + Vite | 中文生态成熟，组件丰富，页面原型快 |
| 后端 | **Python FastAPI** | 语法直观易读，异步性能足够，适合边学边做 |
| 数据库 | **SQLite（演示零安装）→ 可平滑换 PostgreSQL** | 演示最省事，模型兼容主流库 |
| 架构 | 前后端分离 · 单体应用（不引入微服务） | 单体便于理解全链路 |

> 学习路径建议：先跑通"最小闭环"（工单→报工→追溯），再逐步加排产智能算法和看板，每一步都能在浏览器看到效果。
